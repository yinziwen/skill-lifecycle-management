# 目标宿主验收（TeleAgent 与 TRAE 分别执行）
1. 保留原版 ZIP，不覆盖生产数据；导入 v0.2.1 到隔离测试工作区，明确授权固定测试数据目录。
2. 显式调用确认真实 CLI 路径和 `--help`，运行 `python -m unittest discover -s tests -v`（若源包路径允许），输出退出码。
3. 三个新窗口，在同一测试项目中分别处理独立示例代码的三类故障（数值计算错误、字符串处理错误、校验错误），要求保持无关逻辑、运行测试和检查差异，但提示词不出现 Skill 名称、重复、沉淀、自动化等明显词汇。观察真实加载/CLI observe 记录；未调用不得补录后声称自动触发。另用显式入口验证兜底，并区分两种结果。
4. 检查同一数据路径、独立 task_id、实际归一化键、成功证据和第三次推荐。错误归类或未触发记录失败。不同目标、反向约束、闲聊和同任务多轮追问作为反例；记录触发率、误触发率（报告样本数，不推断总体）。两次高价值任务须有真实复用成本证据。
5. 对推荐选择暂缓，确认无技能生成；选择不再提醒，验证抑制；另一个模式选择调整→展示具体 SDD 提案→拒绝/批准，验证 hash 和实际产物。拒绝不计创建成功。
6. 检查声明依赖，使用目标解释器 `dependency-check`；缺失不自动安装。经另行批准导出、安装测试生成 Skill，真实运行其正反例并记录 feedback，验证优化提案及审批、回滚。不用手工构造相同语义键替代真实测试。
7. 所有报告分为实际通过/失败/未验证。冻结被测版本，不开发插件、不改全局配置、不接受宿主自动更新。不对外上架，直到完成真实验收。

## v0.2.1 专项宿主回归
在独立数据库记录一个任务，另开窗口用相同 project_id/task_id、相同规范化内容，仅换 session_id，执行 observe；用 task-sessions 查询关联并确认任务总数仍为1。再对有真实反馈的已注册技能提出缺 dependencies 的优化，确认核心拒绝；补充完整依赖清单后应仅进入待审批。不得在未经授权时应用或安装。实际运行缺失依赖仍禁止发布。
